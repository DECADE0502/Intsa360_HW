# ADR: SMT 位号图本地 PDF 渲染

## 状态

采用，首次实现日期 2026-07-30。公司内部再分发前仍需由发布负责人复核随包许可证清单。

## 背景

SMT 装配审查需要把供应商 PDF 位号图作为主底图，并在完全离线的安装环境中生成页面预览。浏览器内置 PDF 查看器无法稳定提供逐页像素坐标，也不适合在其上实现可验证的热点叠加。旧实现用坐标矩形自绘板面，无法还原真实位号图。

## 决策

- 后端使用 `pypdfium2` 的预编译 Windows wheel 渲染 PDF 页面。
- 使用 `Pillow` 完成 PNG/JPEG 输入的尺寸读取、缩略图和 PNG 编码。
- 只使用本地文件和本地缓存，不加载 CDN、在线字体或远程转换服务。
- 第一阶段只提取 PDF 自带矢量文本，不引入 OCR。
- 页面预览受像素总量和缓存目录边界限制；原始文件永不直接暴露为任意文件路径。
- 自动页面分类只返回候选和证据。文件名、页数或位号数量均不能单独静默决定正反面。

## 许可证与分发要求

`pypdfium2` 本身采用 BSD-3-Clause / Apache-2.0，所带 PDFium 及其依赖还包含其它开源许可证。运行时发布包必须保留 wheel 中提供的 PDFium 与依赖许可证文件，并在发布验收中检查这些文件存在。Pillow 的许可证文件也必须随二进制运行时保留。

本 ADR 不是法律意见。若公司的开源合规策略不允许该二进制组合，应停止发布含 PDF 渲染功能的安装包，但图片底图和手动校准主流程仍可工作。

## 被否决方案

- **浏览器内置 PDF viewer**：无法提供一致的页面像素坐标和受控渲染生命周期。
- **在线转换服务**：不符合离线和公司资料边界。
- **PyMuPDF**：本阶段不采用，避免在未完成商业/开源许可证评估前引入额外分发约束。
- **前端 `pdfjs-dist`**：技术上可行，但会把大 PDF 解码和页面缓存压力放到浏览器，并增加 worker/字体资源的离线打包复杂度。可作为未来替代实现重新评估。

## 失败降级

PDFium 不可用或单页渲染失败时，扫描结果保留该 PDF 和页数错误，状态进入待确认；用户仍可使用 PNG/JPG 位号图，或进入坐标诊断视图。不得退回“根据坐标自绘完整电路板”并宣称渲染成功。
