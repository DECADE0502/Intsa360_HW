# Setup 维护模式与标准卸载设计

## 目标

同一份 `Insta360_HW_Setup.exe` 在未安装时执行全新安装，在检测到现有安装时进入维护模式。Windows“已安装的应用”、Geek Uninstaller、开始菜单卸载入口和 Setup 维护模式必须统一调用 Inno Setup 生成的 `unins000.exe`，不维护第二套卸载实现。

## Setup 维护模式

- 通过稳定 `AppId` 对应的 HKLM 卸载注册项以及默认安装目录共同检测现有安装。
- 检测到现有安装后，在欢迎页之后显示单选维护页：修复/重装、卸载、取消。
- 修复/重装继续现有事务式安装流程，保留外置用户数据与 Cadence 配置。
- 卸载在任何安装事务开始前启动已注册的 `unins000.exe`，随后无确认弹窗地关闭 Setup。
- 取消不更改注册表、程序文件、用户数据或 Cadence 集成。
- 若安装记录存在但卸载器缺失，卸载选项给出明确提示，要求先执行修复安装，禁止绕过生命周期清理直接删除目录。

## 标准卸载契约

- Inno Setup 保持固定 `AppId`，在 HKLM 标准卸载键写入显示名称、版本、发布者、安装目录、图标、`UninstallString` 与 `QuietUninstallString`。
- Windows 设置和 Geek Uninstaller 使用标准 `UninstallString`；Setup 维护模式也启动同一个文件。
- 交互卸载询问是否保留历史、输出、本机配置和用户插件。
- 静默卸载默认保留用户数据，避免无人值守场景误删工程记录。
- 显式 `/PURGEDATA` 参数执行彻底清理；显式 `/PRESERVEDATA` 参数执行保留数据，两者互斥。
- 两种模式都删除平台程序目录、快捷方式、协议注册以及平台拥有的 Cadence loader；不会删除第三方 Tcl。

## 失败处理

- 维护模式启动卸载器失败时停留在维护页并显示错误，不开始安装事务。
- 生命周期卸载失败时 Inno 停止删除程序目录，保留诊断日志与可修复状态。
- 损坏安装通过修复安装恢复标准卸载器，之后再执行卸载。

## 验收

- 全新安装不显示维护页。
- 同版本再次运行 Setup 显示三个维护选项，默认选择修复/重装。
- 选择卸载后只出现标准卸载流程，Setup 不复制或替换文件。
- Windows 设置和 Geek 能识别平台并启动同一卸载器。
- 交互保留、交互彻底清除、静默默认保留及 `/PURGEDATA` 四条路径均有回归测试。
- 安装、OTA、卸载事务测试与完整发布门禁通过。
