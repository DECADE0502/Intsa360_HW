# Insta360 硬件提效平台 0.4.0 全量整改设计

## 1. 目标与发布边界

0.4.0 是一次性完整发布，内部按强制门禁分阶段集成，但不向用户发布中间版本。目标是将当前“功能已经很多、完成度不一致”的平台收敛为一套稳定、可复核、可维护的硬件工程工作台。

完成标准：

- 六个 Web 工具使用统一流程：选择来源、自动识别、用户决策、分类复核、完整预览、导出与入库。
- BOM 处理不得生成原始数据中不存在的推荐物料记录，Cadence 导出失败不得使用旧文件。
- 插件页面状态、配置文件和 Capture Loader 使用同一份状态源。
- 安装、更新、修复、重装、卸载均有真实进度、清晰错误和可验证结果。
- Web UI 全中文，Capture 核心菜单保持 ASCII 英文以兼容 16.6/17.4。
- 用户电脑不需要安装 Python、Node.js、Git，也不在目标电脑执行 npm、pip 或源码构建。
- 从 0.3.3 可通过 OTA 或 Setup 升级到 0.4.0。

## 2. 产品信息架构

左侧一级导航固定为：

1. 工作台
2. BOM 处理
3. BOM 差异比较
4. BOM 风险检查
5. 网表差异比较
6. 贴片封装检查
7. 单网络检查
8. 插件管理
9. 历史与资产
10. 系统状态

更新入口位于系统状态和左栏底部状态区，但“检查更新”与“立即更新”必须是两个独立动作。Web 页面不提供卸载动作，只提供“打开 Windows 应用列表”和 Setup 维护说明。

每个工具使用同一状态机：

```text
idle -> recognizing -> decision_required -> reviewing -> delivering -> completed
                    \-> failed -----------^          \-> failed
```

规则：

- 切换工具只隐藏当前工作区，不销毁状态。
- 刷新浏览器后从 IndexedDB 恢复资产 ID、参数、筛选和用户决策。
- `completed` 页面提供“完成并开始新任务”，明确清空本工具工作区并立即刷新历史资产。
- `failed` 必须显示错误码、中文原因、恢复动作和日志入口。
- 强制检查失败时不得出现“跳过并导出”。

## 3. 视觉方向

采用“精密工程工作台”而非营销型产品页面。页面应像硬件工程师的日常工作台：中性、清晰、横向信息密度高，品牌只在关键位置出现。

### 3.1 视觉令牌

颜色：

- 页面背景：`#F5F7F9`
- 主表面：`#FFFFFF`
- 深色导航：`#15191F`
- 主文字：`#1F2329`
- 次文字：`#667085`
- 边框：`#D9DEE5`
- 品牌黄：`#FFD600`，只用于 Logo、当前导航标记和少量品牌状态
- 操作蓝：`#1677FF`
- 成功绿：`#178A55`
- 警告橙：`#C96A12`
- 错误红：`#C9362B`

不得使用紫色渐变、装饰光球、毛玻璃背景或大面积单色渐变。状态不能只依赖颜色，必须同时使用图标和文字。

字体：

- 中文正文：`Microsoft YaHei UI`, `PingFang SC`, sans-serif
- 数字与英文：`Segoe UI`, sans-serif
- 位号、编码、路径：`Cascadia Mono`, `Consolas`, monospace

尺寸：

- 展开侧栏 184px，折叠侧栏 56px。
- 顶部工具标题区 52px，固定底部动作区 56px。
- 表格常规行高 36px，紧凑模式 32px。
- 工具栏按钮 32px，主要命令按钮最小高度 36px。
- 圆角只使用 4px、6px、8px；不使用胶囊形文本容器。
- 间距使用 4px 基线：4、8、12、16、24、32。

### 3.2 布局规则

- 内容区使用剩余视口全宽，不设置导致右侧空白的大型 `max-width`。
- 页面区域使用分隔线、背景带和栅格组织，不把每个区块都做成浮动卡片。
- 结果型页面默认采用“左侧主表 + 右侧详情”布局；详情区占 34%，可折叠。
- 低于 1440px 时详情改为 Drawer；低于 1280px 时侧栏默认折叠。
- 步骤页顶部只显示当前流程和问题数量，说明文字进入 Tooltip 或帮助抽屉。
- 固定底部动作区同时提供返回、清空/重新选择、主要下一步动作。
- 宽表固定关键列：状态、位号、子项编码；其他列允许横向滚动。

## 4. 动效系统

动效只用于表达状态变化和空间关系，不用于装饰。

### 4.1 Motion tokens

- `motion-instant`: 100ms，用于图标、按钮和复选状态。
- `motion-fast`: 160ms，用于 Tooltip、下拉菜单和筛选项。
- `motion-panel`: 200ms，用于 Drawer、详情区和步骤内容切换。
- `motion-dialog`: 240ms，用于 Modal 和首次启动等待层。
- 标准 easing：`cubic-bezier(0.2, 0, 0, 1)`。
- 禁止弹簧、回弹、抖动、无限旋转装饰和整页大幅位移。

### 4.2 交互动效

- 工具切换：内容 100ms 淡出、120ms 淡入，不卸载工作区。
- 向导前进：新内容从前进方向平移 12px 并淡入；返回时方向相反。
- 详情 Drawer：200ms 水平进入，关闭后焦点回到触发行。
- 表格筛选：结果数字使用 120ms 交叉淡化，表格本身不整页闪烁。
- 新发现问题：目标行背景高亮 600ms 后恢复，只播放一次。
- 操作成功：Toast 进入 160ms、停留 2.5 秒；关键结果同时留在页面内，不能只靠 Toast。
- 服务启动：使用分阶段状态文字和确定进度；超过 300ms 才显示骨架或进度层。
- 更新下载：进度条由真实字节数驱动；校验、暂存、提交、重启分别显示离散阶段，不使用假进度。
- 后端断开：状态点只在重连期间脉冲，正常运行时保持静态。

### 4.3 减少动态效果

当 `prefers-reduced-motion: reduce` 生效时：

- 所有位移动画关闭。
- 淡入淡出缩短到 80ms。
- 进度条保留数值更新，但关闭循环光效。
- 焦点、错误和状态变化仍通过颜色、图标及文字表达。

## 5. 六个工具的页面设计

### 5.1 BOM 处理

流程固定为七步：

1. 来源：Capture 自动传入、上传文件或选择历史 BOM。
2. 信息：成品名称、父项编码、父项描述、PLM/OA 模板。
3. 屏蔽支架：列出 `SH` 候选，展示编码、名称、型号和描述，逐项确认是否进入最终 BOM。
4. 编码冲突：先选择“应用高置信推荐”或“逐项处理”；低置信组无论何种模式都必须人工确认。
5. 分类检查：基础结构、位号型号、优选等级、版本敏感、重复数量五个子页。
6. 最终预览：直接展示生成文件的完整 19 列数据，并分别切换 PLM/OA。
7. 交付：下载单板名加时间戳 ZIP、查看入库结果、完成并开始新任务。

推荐合并必须选择一条真实存在的完整候选记录。只有空值补全、截断前缀补全或核心字段完全相同时才是高置信推荐；其他冲突保留人工选择。自定义逐字段组合必须标记“原始记录中不存在此组合”并二次确认。

SH 表示屏蔽支架，不能进入 NC BOM；屏蔽罩不属于贴片流程要求。检测到 DDR、eMMC 时必须提示确认硬件版本号。

### 5.2 BOM 差异比较

来源区并排选择原 BOM 和新 BOM。结果页包含：

- 顶部横向摘要带：新增、删除、换料、属性变化、位号迁移、数量变化、高风险。
- 左侧全宽差异表：按变化类型、风险、编码和位号筛选。
- 右侧详情：原记录、新记录、变化字段、用量影响和建议动作。
- 视图切换：按位号、按物料编码、仅高风险。
- 导出：原表标注、差异明细、用量小结、风险摘要。

重复位号必须在比较前阻止流程，不能使用“最后一行覆盖”。同编码描述变化必须单独分类，不能归入未变化。

### 5.3 BOM 风险检查

替换通用 Legacy 页面，使用专用工作台。分类为：

- 结构完整性
- 位号与型号
- 编码与描述冲突
- 优选等级
- 版本敏感器件
- 重复位号与数量
- 最终确认

每条问题展示严重度、证据、建议、是否必须确认。独立风险工具和 BOM 处理内嵌检查必须使用同一规则引擎和同一文案。

### 5.4 网表差异比较

用户选择两个 allegro 目录，自动寻找 pstxnet.dat 和可选 pstxprt.dat。结果分类：新增网络、删除网络、重命名、拆分、合并、混合拓扑、节点变化、封装变化。

页面使用左侧分类列表、中间网络表、右侧节点详情。关键电源、时钟、复位网络固定高风险标识。缺文件时明确显示选中的目录和缺失文件，不使用笼统错误。

### 5.5 贴片封装检查

来源必须是 allegro 目录和已经处理过的 PLM/OA BOM。状态包括：精确匹配、别名匹配、近似、尺寸冲突、缺失、多封装、NC、非 SMT。

详情区同时显示位号、网表封装、BOM 名称/型号/描述、命中的规则和建议。0402/0603 等尺寸代码冲突优先级高于通用 token。

### 5.6 单网络检查

页面分为 NC、单一位号、关键网络、机械网络和已排除五类。NC 默认只匹配 `NC`、`NC数字`、`NC_数字`、`NC-数字` 及明确配置，`NCLK`、`nCS0` 不得误判。

用户可在当前任务调整规则并重新计算；只有点击“保存为默认规则”才持久化。

## 6. 平台页面设计

### 6.1 工作台

首屏直接显示六个工具入口、最近任务、待确认问题和真实服务状态。工具入口使用紧凑列表或两列工作区，不使用大型营销卡片。最近任务可继续、查看结果或开始同类新任务。

### 6.2 插件管理

- 系统插件：只读、默认折叠，显示扫描路径和版本。
- 平台插件：分为已挂载和未挂载，开关后立即刷新。
- 用户插件：显示来源、兼容版本、入口 Tcl 和验证结果。
- 快速 NC 明确标记“需要重启 Capture”；其他插件显示热更新命令和执行结果。
- 高风险插件必须先确认再修改状态，取消确认不得先调用后端。

### 6.3 历史与资产

统一管理 BOM、网表目录、报告和任务。每项使用 UUID，不再按文件名查找。支持筛选、固定、删除、重新用于其他工具和查看来源关系。刚完成的任务必须立即出现。

### 6.4 系统状态与更新

显示后端健康、版本、revision、安装目录、数据目录、Cadence 集成和插件状态。状态必须来自实时健康检查，不能仅依赖旧 PID。

“检查更新”只获取 manifest 和公告；确认后才允许“立即更新”。更新 Modal 必须关闭公告 Modal 后再打开。取消只在提交前可用，提交后按钮变为不可用并解释原因。

## 7. 后端与数据设计

正式后端使用 FastAPI、Uvicorn 和 Pydantic。旧 `suite_app.py` 仅保留启动兼容层，业务迁移到独立 router、service 和 repository。

统一 API 返回 `ok`、`request_id`、`data`、`error`。变更请求必须携带会话自定义头，并校验 Host 与 Origin。默认限制单文件 100MB、单请求 200MB。

资产与历史使用 `%LOCALAPPDATA%\Insta360_HW\data\platform.db`。SQLite 保存资产、任务、输入输出关系和迁移状态；文件继续保存在文件系统。旧 JSON 历史通过幂等迁移导入。

临时上传保留 24 小时，失败更新暂存保留 7 天，正式资产不自动删除；占用达到 10GB 时提醒用户清理。日志按 20MB、5 份轮转。

## 8. Cadence 与插件设计

自动发现 C/D 盘及用户/vendor 配置中的 16.6 和 17.4。安装、修复和移除只操作本平台拥有的 Loader、插件和状态，不修改 PLMTools 或其他第三方脚本。

每次 BOM 导出使用唯一 job 目录和 JSON 文件。转换失败立即返回当前 job 错误，禁止从 inbox 选择任何旧 Excel。两个 Capture 进程并行导出不能覆盖。

每个可管理功能拥有独立入口 Tcl，共用函数进入只加载一次的 common 模块。系统脚本只读；平台和用户脚本可管理。Loader、后端和前端读取同一份 plugin_state.json。

仓库中的 Tcl 保持 UTF-8，部署阶段针对 Capture 生成 GBK 文件并验证可解码。核心菜单使用 ASCII，避免不同 Windows 代码页导致乱码。

## 9. 安装、更新与卸载设计

程序目录使用版本化 runtime：

```text
%ProgramFiles%\Insta360\HWAgent\
  Insta360_HW.exe
  installation.json
  runtime\0.4.0+<revision>\...
```

Launcher 读取原子 active 指针启动当前 runtime。更新过程为下载、签名与 SHA 校验、暂存、授权、提交、切换、重启、健康验证、清理。提交前取消必须无残留；验证失败切回上一 runtime。

Setup 使用稳定 AppId。检测到已有安装后显示升级、修复、重装、卸载，不再次进入普通安装向导。修复重新部署缺失文件和 Cadence 集成，但保留用户数据。

标准卸载停止所有平台进程，移除 Cadence 集成、快捷方式、注册表和程序目录；提供明确的“保留历史和用户插件”选项。完成后停留在完成页，等待用户点击关闭。

发布机本地生成预构建 Runtime ZIP、Setup、manifest、SHA256 和 Ed25519 签名。GitHub 仅校验和托管资产，不要求 GitHub Actions 远程构建。更新器禁止回退到源码 ZIP。

## 10. 测试与发布门禁

自动测试必须包含：

- 后端单元、契约、SQLite 迁移、并发、文件锁、中文路径和短路径测试。
- React Testing Library 覆盖弹窗层级、确认取消、返回清空、刷新恢复、插件开关和更新状态机。
- Playwright 跑通六工具、插件、历史和更新流程。
- 1366x768 与 1920x1080 截图检查，无遮挡、溢出、空白区和控制台错误。
- `prefers-reduced-motion` 下无位移动画。
- Cadence 16.6/17.4 人工矩阵。
- 0.3.3 到 0.4.0 OTA、Setup 升级、修复、重装、Windows 卸载和 Geek 卸载调用。
- 断网、404、签名错误、磁盘满、下载取消、提交后崩溃和回滚故障注入。

性能门槛：

- 冷启动 8 秒内健康，健康后 UI 2 秒内可交互。
- 1500 行 BOM 处理 5 秒内完成。
- 2000 节点网表分析 8 秒内完成。
- 5000 行表格滚动和筛选保持可用，无整页重绘。
- 初始路由 gzip 不超过 450KB，六工具按路由懒加载。

只有全部自动测试、真实样本对照、Cadence 矩阵、生命周期矩阵和独立代码审查通过后，才能生成公开 0.4.0 manifest。
