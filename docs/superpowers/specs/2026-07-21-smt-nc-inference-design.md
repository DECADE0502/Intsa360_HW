# SMT NC 位号推导设计

## 目标

SMT 可视化不再依赖成品 BOM 同目录中的 `NC未贴汇总.xlsx`。平台使用设计总位号与成品 PLM/OA BOM 的集合差推导不贴器件，并区分确定 NC 与数据异常，避免把所有缺失位号混为一类。

## 输入与权威范围

- `XY.txt`：板上具有坐标、可在 SMT 板图中展示的总位号集合。
- 成品 PLM/OA BOM：实际计划贴装或进入成品 BOM 的位号集合，不包含 NC 器件。
- `pstxprt.dat`：可选的 Cadence 设计网表位号集合，用于增强推导置信度和发现数据异常。
- 同目录 `NC未贴汇总.xlsx`：仅作为补充证据兼容旧流程，不再是 NC 的唯一来源。

## 方案选择

1. 继续只读取显式 NC 汇总：改动最小，但网页单文件上传天然丢失伴随文件，不能解决根因。
2. 只使用 `XY - BOM`：无需网表即可工作，但无法区分真正 NC 与 XY 数据异常。
3. 使用 XY、成品 BOM、可选网表和显式 NC 的证据分级：既覆盖日常上传，又保留异常识别能力。采用此方案。

## 分类规则

设 `X` 为 XY 位号、`B` 为成品 BOM 位号、`N` 为网表位号、`E` 为显式 NC 汇总位号。

有网表时：

- 已贴装：`X ∩ B`
- 确定 NC：`(X - B) ∩ (N ∪ E)`
- 待确认异常：`X - B - N - E`
- 缺少布局：`(B ∪ N) - X`
- BOM 中存在但网表缺失：`B - N`

无网表时：

- 已贴装：`X ∩ B`
- 显式确认 NC：`X ∩ E - B`
- 候选 NC：`X - B - E`
- UI 必须说明这些结果是依据 `XY - BOM` 推导的候选 NC，而不是经过网表交叉验证的确定 NC。

显式 NC 汇总与成品 BOM 冲突时，不直接覆盖成品 BOM。该位号保留为已贴装，并在一致性检查中报告“BOM 与显式 NC 冲突”。

## 返回契约

组件状态扩展为：

- `installed`：成品 BOM 中存在。
- `nc`：有网表交叉验证或显式 NC 证据的确定 NC。
- `candidate_nc`：无网表时由 `XY - BOM` 推导的候选 NC。
- `unverified`：有网表时仅在 XY 中存在，需确认数据来源。

`nc_summary` 增加证据摘要：

- `confirmed_refs`
- `candidate_refs`
- `unverified_refs`
- `inference_mode`：`with_netlist` 或 `without_netlist`
- `explicit_summary_used`：是否读取到显式 NC 汇总

旧字段 `total` 与 `refs` 保留，其中 `refs` 是确定 NC 与候选 NC 的并集，不包含 `unverified`。

## 界面行为

- NC 布局列表默认显示确定 NC 与候选 NC，待确认异常单独显示数量和筛选入口。
- 确定 NC、候选 NC、待确认异常使用不同标签和板图颜色。
- 输入区说明成品 BOM 应为已经处理完成、可导入 PLM/OA 且不含 NC 的 BOM。
- 有网表时显示“网表已交叉验证”；无网表时显示“未提供网表，当前为候选 NC”。
- 三向一致性不再把确定 NC 报成“BOM 缺失”，只报告真正的数据异常。

## 首件核对表

- `installed` 行继续输出应贴料号和 BOM 信息。
- `nc` 行标记“NC，不贴装”。
- `candidate_nc` 行标记“候选 NC，需确认”。
- `unverified` 行标记“XY 独有，检查坐标/网表/BOM”。

## 测试与验收

- 单独上传成品 BOM、同目录没有 NC 汇总时，能从 `XY - BOM` 得到候选 NC。
- 同时提供网表时，`XY ∩ 网表 - BOM` 得到确定 NC。
- XY 独有但网表不存在的位号不会被当成确定 NC。
- 成品 BOM 与显式 NC 汇总冲突时，以成品 BOM 为准并报告冲突。
- 确定 NC 不再出现在 `missing_bom` 中。
- API 契约、前端类型、板图颜色、列表筛选、E2E 与生产构建全部通过。
