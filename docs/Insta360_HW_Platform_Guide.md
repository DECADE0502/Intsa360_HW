# Insta360 硬件提效平台使用说明

## 1. 这是什么

Insta360 硬件提效平台是一套给硬件工程师使用的本地工具平台，主要用于 BOM 处理、BOM 检查、BOM 差异比较、网表差异比较、贴片封装检查、贴片位号查看、单网络检查，以及 OrCAD Capture 脚本管理。

它不是单个 Excel 小工具，而是把硬件研发里反复做、容易漏、容易出错的检查流程做成一套固定工具。目标是让工程师在出 BOM、改版评审、贴片前检查、Capture 脚本使用时少做重复劳动，少靠人工肉眼查表。

平台主要解决这些问题：

- Capture 导出的 BOM 字段多、格式乱，手工整理容易漏。
- NC、未贴、测试点、机构件、屏蔽支架等对象容易混进最终 BOM。
- 同一个物料编码可能出现不同描述、型号、名称或等级，人工合并容易误选。
- 改版时 BOM 和网表都要对比，人工逐行看很慢。
- eMMC、DDR、BGA、连接器等高风险物料需要额外提醒。
- OrCAD Capture 的 Tcl 小脚本越来越多，手动安装和同步很麻烦。

一句话：平台把硬件工程师常做的 BOM 和网表检查固化成可重复、可追溯、可导出报告的流程。

## 2. 什么时候用

### 2.1 从 Capture 导 BOM 给 PLM/OA

用 **BOM 处理**。

适合场景：

- 原理图阶段导出 BOM。
- 需要生成 PLM/OA 可导入格式。
- 需要过滤 NC/未贴。
- 需要确认 SH 位号属于屏蔽支架、屏蔽罩还是其他类型。
- 需要处理相同物料编码但描述不一致的问题。
- 需要最终 BOM 预览和打包交付。

### 2.2 导入 PLM/OA 前自查

用 **BOM 风险检查**。

适合场景：

- BOM 已经整理好，准备提交前。
- 需要检查 PCB 裸板、屏蔽支架、NC、重复位号、数量一致性。
- 需要提醒 eMMC、DDR/LPDDR、NAND、UFS 等硬件版本敏感物料。
- 希望提前发现导入或评审风险。

### 2.3 改版后确认 BOM 变化

用 **BOM 差异比较**。

适合场景：

- V01 到 V02 改版。
- 二供替换。
- 试产后 BOM 调整。
- 想确认哪些位号新增、删除、换料、参数变化。
- 想从料号用量角度看采购/PLM 变化。

### 2.4 改版后确认网表变化

用 **网表差异比较**。

适合场景：

- 原理图或 PCB 修改后，需要确认网络节点变化。
- 需要检查关键网络是否新增、删除、少接、多接。
- 需要确认封装变化。
- 需要对比两个 Allegro 导出的 `allegro` 目录。

### 2.5 贴片前确认封装和 BOM 是否一致

用 **贴片封装检查**。

适合场景：

- 已经有 Allegro 网表目录。
- 已经有处理后的 PLM/OA 成品 BOM。
- 需要确认网表 footprint 和 BOM 描述、型号、封装是否一致。
- 需要检查同一物料编码是否对应多个封装。
- 需要确认 BOM 缺位号或 BOM 多余位号。

### 2.6 出图前查 NC 和单网络

用 **单网络检查**。

适合场景：

- 出图前检查 NC 网络。
- 检查只有单一位号的网络。
- 排查悬空、漏连、网络命名异常。

### 2.7 管理 Capture 小脚本

用 **插件管理**。

适合场景：

- 想把某个 Tcl 功能挂到 Capture 菜单。
- 想取消某个脚本的菜单入口。
- 想同步团队新增脚本。
- 不想每个人手工复制 Tcl 文件。

## 3. 安装与第一次启动

### 3.1 安装前准备

安装前建议确认：

- 电脑已安装 OrCAD Capture。
- 如果要使用网表差异、贴片封装、单网络检查，需要能从 Allegro 导出 `pstxnet.dat`、`pstxprt.dat`。
- 如果公司电脑拦截未知程序，第一次运行安装包时可能需要选择“仍要运行”或让 IT 放行。
- 安装和更新过程中不要关闭安装窗口或平台窗口。

### 3.2 使用安装包安装

拿到安装包后，双击：

```text
Insta360_HW_Setup.exe
```

按安装向导操作即可。一般情况下使用默认安装路径，不需要手动改目录。

常见安装目录是：

```text
C:\Program Files\Insta360\HWAgent
```

安装过程中会自动完成：

- 安装平台主程序。
- 放置平台运行所需文件。
- 创建主入口 `Insta360_HW.exe`。
- 准备本地数据目录，用于保存上传文件、输出报告和历史记录。
- 部署 OrCAD Capture 菜单脚本。
- 准备更新、卸载和日志功能。

### 3.3 安装完成后会有什么

安装完成后，电脑上会有：

| 项目 | 说明 |
|---|---|
| `Insta360_HW.exe` | 平台主入口，双击打开平台 |
| 平台安装目录 | 保存平台程序、工具、脚本和本地数据 |
| 本地 Web 平台 | 浏览器中打开，默认地址 `http://127.0.0.1:8765` |
| OrCAD Capture 菜单 | Capture 重启后出现 `insta360_HW` 菜单 |
| 数据目录 | 保存上传文件、输出报告、历史记录和运行日志 |
| 更新/集成入口 | 平台左侧底部可检查更新、立即更新、查看更新公告、移除 Cadence 集成 |

注意：平台是本地运行的工具，BOM、网表和报告默认都在本机处理。

### 3.4 第一次打开平台

安装完成后，双击：

```text
Insta360_HW.exe
```

平台会启动本地服务，并自动打开浏览器页面：

```text
http://127.0.0.1:8765
```

第一次启动可能会等待几秒。如果看到等待页面或启动动画，等它自动跳转即可。

如果服务已经打开，再次双击 `Insta360_HW.exe` 会复用已有服务，不需要重复启动多个窗口。

### 3.5 第一次打开后建议做什么

第一次打开平台后，建议按这个顺序检查：

1. 看左侧是否能看到 BOM 处理、BOM 差异比较、BOM 风险检查、网表差异比较、贴片封装检查、单网络检查、插件管理。
2. 打开 **系统状态**，确认没有明显失败项。
3. 打开 **插件管理**，看平台是否识别到 Capture 脚本。
4. 打开 OrCAD Capture，重启一次 Capture。
5. 在 Capture 菜单中确认是否出现 `insta360_HW`。
6. 用一份测试 BOM 试跑一次 BOM 处理或 BOM 风险检查。

### 3.6 Capture 里安装完成后会多什么

重启 OrCAD Capture 后，菜单中应出现：

```text
insta360_HW
```

菜单里固定有两个入口：

- `Open Platform`：打开平台首页。
- `Export and Process BOM`：导出当前设计 BOM，并自动进入 BOM 处理。

其他脚本是否出现在 Capture 菜单中，由平台的 **插件管理** 控制。比如 NC 切换、GND 网络名显示/隐藏、网络名替换、脱敏等脚本，只有在插件管理里启用后才会挂到 Capture 菜单。

### 3.7 如果 Capture 菜单没有出现

如果安装后 Capture 里没有 `insta360_HW` 菜单，按下面顺序处理：

1. 先完全关闭并重新打开 OrCAD Capture。
2. 打开平台，进入 **系统状态**，看 Cadence 集成是否正常。
3. 打开 **插件管理**，复制底部的 Capture 热更新指令。
4. 在 Capture Command Window 执行：

```tcl
source [file join $env(HOME) "cdssetup/OrCAD_Capture/tclscripts/capAutoLoad/iac_bom_tool.tcl"]
```

5. 如果仍然没有菜单，重新运行安装包或联系维护人员检查 Capture 的 Tcl 自动加载目录。

### 3.8 日常怎么打开

日常使用有两种入口：

- 直接双击 `Insta360_HW.exe`，进入平台首页。
- 在 Capture 里点击 `insta360_HW -> Export and Process BOM`，直接导出并进入 BOM 处理。

如果只是做 BOM 对比、风险检查、网表对比、封装检查，直接从平台左侧进入对应工具即可。

## 4. 推荐主流程

### 4.1 正常出 BOM 流程

```text
Capture 点击 Export and Process BOM
  -> 自动打开 BOM 处理
  -> 确认成品名称、父项编码、父项描述
  -> 在装机审查中一次性确认疑似物料、工艺件、屏蔽支架、属性冲突和数据不足项
  -> 确认相同编码冲突如何合并
  -> 生成 PLM/OA BOM
  -> 查看最终 BOM 预览
  -> 进入 BOM 风险检查
  -> 下载交付 zip
```

### 4.2 改版评审流程

```text
旧 BOM + 新 BOM
  -> BOM 差异比较
  -> 看新增、删除、换料、参数差异、料号用量变化

旧 allegro 目录 + 新 allegro 目录
  -> 网表差异比较
  -> 看网络节点、Pin、封装变化

新 allegro 目录 + 新 PLM/OA BOM
  -> 贴片封装检查
  -> 看缺位号、多余位号、多封装、高风险封装
```

### 4.3 出图前检查流程

```text
Allegro 网表目录
  -> 单网络检查
  -> 查 NC 网络和单一位号网络

最终 BOM
  -> BOM 风险检查
  -> 查 PCB、屏蔽支架、NC、重复位号、数量和优选等级
```

## 5. BOM 处理

### 5.1 作用

把 Capture 原始 BOM 处理成可导入 PLM/OA 的成品 BOM，同时输出明确 NC、其他非贴片项、逐位号判定记录、机器可读决策清单和最终 BOM 预览。

### 5.2 输入

- Capture 导出的原始 BOM Excel。
- 成品名称。
- 父项编码。
- 父项描述。
- 输出格式：PLM、OA，或两者都输出。
- 可选附加物料：PCB 裸板、屏蔽支架、其他结构/辅料。

如果从 Capture 菜单 `Export and Process BOM` 进入，原始 BOM 会自动带入，不需要手动上传。

手动从 Capture 导出时，BOM 来源页下方提供 **Capture 手动导出字段**。点击“复制字段”，把同一段内容分别粘贴到 Capture 导出窗口的 `Header` 和 `Combined property string`。这套完整采样字段除物料编码、型号、描述和封装外，也保留旧描述、等级备注、制造商、datasheet、Color、库来源、实现路径和坐标等诊断信息；诊断列只留在原始 BOM 和判定证据中，不会额外写入最终 PLM/OA 模板。

### 5.3 操作步骤

1. 打开 **BOM 处理**。
2. 如果是手动进入，上传 Capture 原始 BOM。
3. 填写成品名称、父项编码、父项描述。
4. 选择输出 PLM、OA 或两者。
5. 如有附加物料，补充编码、名称、型号、描述、数量和位号。
6. 点击开始处理。
7. 在装机审查的“纳入贴片 BOM / 非贴片区”双区工作台中核对待确认项目，可用左右箭头双向归类。
8. 纳入 BOM 时，确认子项编码，并至少保留名称、型号或描述之一。
9. 如需批量处理当前页，点击“采纳当前页安全建议”并核对确认摘要；该操作只处理强证据、非冲突、非 SH 项。
10. 如果提示相同编码属性冲突，选择完整候选、按位号拆组并改码、把指定变体移到非贴片区，或返回 Capture 修正。
11. 查看最终 BOM 预览。
12. 继续做风险检查。
13. 下载输出文件或 zip 包。

### 5.4 装机审查

平台会先归并重复行和已证实的多单元器件，再把需要人工判断的物理位号集中到一个装机审查页面。左右两区展示贴片与非贴片归类，右侧证据面板按“料号身份、位号角色、封装/库信息、Value/型号/名称、描述”的顺序显示依据。

审查类别包括：

- **疑似物料**：子项编码为空，但 Value、型号、描述、名称或库属性中存在物料编码、封装等证据。
- **疑似工艺件**：位号与封装/库信息共同提示测试点、短接图元、安装孔或定位点，需要确认是否进入贴片区；描述单独命中不能推翻有效料号。
- **屏蔽类**：SH 位号触发强制复核，必须选择屏蔽支架、屏蔽罩或其他，并确认目标区域。
- **属性冲突**：有效编码与 NC 标记同时出现，或编码列疑似填入描述等互相矛盾的情况。
- **数据不足**：有效字段过少、只有占位残渣或异常字符，必须人工决定，平台不会静默删除。
- **已判 NC**：Value 明确为 `NC`、`DNP`、`DNI`、`No Load`、`NOFIT`、`不贴`、`未贴` 或 `空贴`，只读展示判断依据；SH 即使同时为 NC 也仍需先做屏蔽类型审查。

审查规则：

- 完全重复行和证据一致的多单元器件会归并为唯一物理位号，来源行仍可追溯。
- 位号前缀只作为分类提示和排序依据，不会单独得出装机结论。
- 建议字段可以预填，但建议本身不会自动完成审查。
- 没有明确建议的弱证据项目和数据不足项必须逐组选择目标区域。
- 选择“纳入 BOM”时必须填写子项编码，并至少有名称、型号或描述之一。
- 进入非贴片区时必须区分明确 NC、工艺项、范围排除或用户排除；只有明确 NC 会进入 NC 汇总。
- 决议按料号、角色、Value、型号、名称、封装、描述和规则版本的完整指纹保存；任一关键属性变化后只显示历史提示，不会自动套用旧决定。

### 5.5 SH 屏蔽类确认

平台会把 SH 开头位号放入屏蔽类强制审查，但不会仅凭位号猜测具体物料类型。

- 选择 **屏蔽支架**：进入贴片区和最终 BOM。
- 选择 **屏蔽罩**：进入非贴片区，并标记为范围排除。
- 选择 **其他**：还需由用户明确选择贴片区或非贴片区。
- SH 与 NC、测试点封装或描述冲突时仍不能只读跳过，必须完成类型和区域确认。

### 5.6 疑似工艺件确认

贴装判定以物料属性为主，不会仅凭 `TP`、`JP`、`H`、`MH`、`MTG` 等位号前缀过滤物料。有料号的行如果命中测试点、跳线、安装孔、定位孔、铜柱、螺母柱、结构件、Fiducial、Screw 等关键词，会进入装机审查；空编码行如果同时存在可识别的 MPN，则优先按疑似物料提示纳入，避免机构类位号覆盖真实物料证据。`跳线电阻`、`零欧电阻` 等明确器件名称不会被当成工艺跳线。

- 移到“纳入贴片 BOM”：进入最终 PLM/OA BOM。
- 移到“非贴片区”：选择具体排除类型，并保留人工决议记录；工艺项和范围排除不会混入 NC 汇总。
- 从 Capture 再次点击“导出并处理 BOM”时，即使导出路径与上次相同，平台也会按新文件重新解析，不复用上次产物或判断结果。
- 每次重新生成成品 BOM 后都会针对本次输出重新执行风险审查，不会沿用旧 BOM 的风险报告。
- 可以显式采纳当前页的推荐结果，但平台不会因为推荐存在而自动放行。
- 普通有料号物料即使使用工艺型位号，只要属性未命中工艺关键词，也会按正常物料处理。

### 5.7 编码冲突合并

如果同一个物料编码出现不同 Value、型号、描述、名称、封装、制造商、等级或单位，平台会暂停并提示用户确认。

可选方式：

- 采纳高置信推荐：只适用于空值由同一完整候选补齐、格式等价或已确认的非数字截断补全。
- 选择完整候选：整组选用一个原始候选，不逐字段拼接。
- 按位号拆组并改码：每个变体填写不同的新料号。
- 移到非贴片区：把不属于当前 PCBA/SMT 范围的变体移出。
- 返回 Capture 修正：不在平台中放行冲突。

建议：

- 优先保留和 PLM/OA 口径一致的字段。
- 如果同一编码确实是同一颗料，只是描述格式不同，可以合并。
- 如果同一编码对应不同规格，要先回到物料库或原始 BOM 查清楚，不要直接放行。

### 5.8 输出

常见输出包括：

- PLM BOM。
- OA BOM。
- 明确 NC 汇总。
- 非贴片项汇总。
- BOM 判定记录。
- 机器可读 BOM 决策清单。
- 最终 BOM 预览。
- 打包 zip。

## 6. BOM 风险检查

### 6.1 作用

对单份 BOM 做导入前体检，提前发现字段、贴装范围、替代关系和交付风险。工具可以独立运行，不要求先生成装机决策清单；如果从 BOM 处理流程进入，则会额外核对处理后的 BOM 与装机决策是否一致。

### 6.2 操作步骤

1. 打开 **BOM 风险检查**。
2. 从历史记录选择已处理 BOM，或上传 Capture、PLM 单板、OA BOM。
3. 点击 **开始风险检查**。
4. 先看顶部的阻断、警告、提示、通过数量和识别格式。
5. 按检查结论、优选等级、位号类型、替代组、专项物料、版本敏感等页签逐项确认。
6. 下载多工作表风险检查报告。

### 6.3 会检查什么

| 检查项 | 说明 |
|---|---|
| 来源格式与字段 | 识别 Capture、PLM 单板、OA 等格式，检查必要字段和编码精度 |
| PCB 裸板/父项 | PCB 父项只用于范围确认，不会计入实际贴装数量 |
| 实际贴装口径 | 父项和替代料不重复计入实际贴装位号与数量 |
| 替代组结构 | 检查唯一主料、连续优先级、组编码、数量、位号、策略和方式 |
| 屏蔽类 | 根据 SH 位号及名称、型号、描述识别，区分屏蔽支架、屏蔽罩和待确认类型 |
| NC/未贴器件 | 防止未贴器件混入最终 BOM |
| 机构件/贴片机械件 | 汇总螺柱、铜柱、螺母柱等对象，提醒确认装配范围 |
| 测试点/跳线/工艺对象 | 汇总测试点、短接、Mark/Fiducial 等对象，提醒确认是否应进入成品 BOM |
| 重复位号 | 同一位号不应被多个物料重复占用 |
| 空编号行 | 有位号但物料编码为空需要处理 |
| 数量=位号数 | 检查数量和位号数是否一致 |
| 位号/器件类型 | 如 R 位号却识别为电容/电感，会提示 |
| 物料优选等级 | 非“优选/正常”的等级会提醒 |
| 发料、MRP、跳层、单位和备注 | 汇总分布并提示异常值或缺失值 |
| 硬件版本敏感物料 | eMMC/DDR 需要核对硬件版本号、容量、速率和替代关系 |
| 决策一致性 | 从 BOM 处理流程进入时，核对贴片区与非贴片区决策是否正确落入输出 |

### 6.4 怎么看结果

- `阻断`：存在重复位号、空编码、数量不一致、编码精度或必要字段等结构问题，当前 BOM 不应交付。
- `通过`：本项自动检查通过。
- `提示`：不一定是错误，但需要知道它存在。
- `警告`：建议处理或人工确认后再提交。

重点关注：

- 重复位号。
- 数量和位号数不一致。
- NC/未贴混入最终 BOM。
- 替代组没有唯一主料、优先级不连续或组内数量不一致。
- SH、机构件、工艺项和版本敏感物料是否符合本次装配范围。

报告包含风险概览、等级明细、位号类型冲突、替代组、屏蔽/机构/工艺项、版本敏感料和 NC 明细。替代料的空位号和组内数量不会累加到整板贴装数量。
- SH 屏蔽支架缺失。
- eMMC/DDR 版本相关提醒。

## 7. BOM 差异比较

### 7.1 作用

比较两份 BOM，帮助确认改版到底改了什么。

它不是简单比较 Excel 单元格，而是同时检查四层内容：

- **实际贴装**：同一父项下，每个真实位号最终由哪个优先级 0 主料贴装。
- **替代关系**：主料、替代料、替代组编码、优先级和组内数量是否变化。
- **原始行**：父项、子项、数量、位号及模板字段的逐行变化。
- **元数据**：名称、型号、描述、等级等不直接改变贴装关系的变化。

替代料的空位号和数量不会累加为实际贴装数量。例如 `A=0、B=1、C=2` 且主料 A 有 4 个位号时，平台按 4 个实际贴装位号和 1 个三料替代组处理，不会计算成 12 颗器件。

实际贴装结果按“父项 + 变化类型 + 旧主料 + 新主料”归并为业务变化组。同一批位号发生完全相同的主料变化时只显示一组，并在组内列出全部位号；旧料、新料、父项或变化类型任一不同都会保持为独立组。页面同时显示变化组数和涉及位号数，导出的分层报告也按一组一行呈现，机器可读 JSON 仍保留逐位号事实供追溯。

替代组按业务语义比较，而不是直接比较 Excel 行。父项、组编码、主料、替代料、优先级、数量和实际位号构成核心关系；替代策略和替代方式只有在新旧两边都提供明确值且值不同时才算变化。某份系统回导文件把策略或方式留空时，平台将其标记为“来源未提供”的警告，不会把未知值误判为关系变化；如果确实要生成新增或变更的 PLM/OA 替代关系，输出阶段仍会要求必要字段完整。

### 7.2 操作步骤

1. 打开 **BOM 差异比较**。
2. 上传旧版/基准 BOM。
3. 上传新版/待确认 BOM。
4. 确认平台识别出的父项、实际位号数和替代组数；识别有阻断项时先修正源 BOM。
5. 点击开始对比。
6. 先看顶部的父项、实际位号、替代组和阻断项统计。
7. 在 **实际贴装** 页按变化组确认新增、删除、换料和位号迁移；展开组内位号核对影响范围。
8. 在 **替代关系** 页确认主替代优先级互换、替代料增删和组结构。
9. 在 **原始行/元数据** 页确认模板字段和描述变化。
10. 在 **风险与交付** 页确认没有阻断项后下载分层报告和机器可读 JSON。

### 7.3 结果怎么判断

| 类型 | 怎么理解 |
|---|---|
| 无变化 | 实际贴装、替代关系和关键字段均一致 |
| 仅描述/元数据变化 | 编码、位号和替代关系没变，一般不直接表示贴错风险 |
| 仅替代优先级变化 | 替代组成员没变，但主料顺序发生变化 |
| 主料变化并迁移位号 | 位号完整迁移到新的优先级 0 主料 |
| 新增/删除替代料 | 供料选择变化，实际贴装位号没有重复计数 |
| A 换成 B | 旧料退出、新料接管位号，不属于 AB 共存替代 |
| 数量或位号变化 | 实际装机数量、位号集合或位号归属变化 |
| 替代组结构错误 | 缺少唯一主料、优先级不连续、组编码错误或组内数量不一致 |
| 可能贴错，需阻断 | 同一位号映射多个主料、主料缺位号或替代料错误占用位号 |

### 7.4 推荐看法

改版评审时优先看：

1. 阻断项和替代组结构错误。
2. 主料变化、A 换 B 和位号迁移。
3. 新增或删除的实际贴装位号。
4. 替代料新增、删除和优先级变化。
5. 数量变化。
6. 仅描述/元数据变化。

同一父项下比较，不会把不同 PCBA 的相同位号混在一起。位号 `60` 在替代料行中按空位号处理；物料编码始终按文本读取，不会主动转成数字或科学计数法。

## 8. 网表差异比较

### 8.1 作用

比较两个 Allegro 网表目录，确认网络、节点、Pin 和封装变化。

### 8.2 输入

选择两个 Allegro 目录，例如：


目录中应包含：

```text
pstxnet.dat
pstxprt.dat
```

直接选择目录即可，平台会自动识别文件。

### 8.3 操作步骤

1. 打开 **网表差异比较**。
2. 选择旧版 Allegro 目录。
3. 选择新版 Allegro 目录。
4. 点击开始比较。
5. 查看新增网络、删除网络、节点变化、Pin 变化、封装变化。
6. 对关键网络优先人工确认。
7. 下载差异报告。

### 8.4 重点关注

重点看这些网络或对象：

- DDR。
- eMMC。
- MIPI。
- USB。
- 晶振/时钟。
- 复位。
- 电源使能。
- 关键电源网络。
- 高速连接器。

如果 BOM 显示某个器件换料，但网表没有对应变化，要确认是否只是 BOM 替代；如果网表变化但 BOM 没变化，要确认是否漏更新 BOM。

## 9. 贴片封装检查

### 9.1 作用

检查 Allegro 网表封装和最终 PLM/OA BOM 的描述、型号、封装字段是否一致。

主要防止：

- BOM 封装描述和 PCB footprint 不一致。
- 同一物料编码对应多个不同 footprint。
- 网表有位号但 BOM 中缺失。
- BOM 有位号但网表中不存在。
- 高风险封装没有被注意到。

### 9.2 输入

- Allegro 网表目录，必须包含 `pstxprt.dat`。
- 已处理后的 PLM/OA 成品 BOM。
- 同次 BOM 处理生成的 **BOM 语义清单**。从历史 BOM 选择时会自动关联；手工上传时建议同时选择。

注意：这里不要上传 Capture 原始 BOM。贴片封装检查应该使用 BOM 处理后生成的 PLM/OA BOM。

### 9.3 操作步骤

1. 打开 **贴片封装检查**。
2. 选择 Allegro 网表目录。
3. 选择已处理后的 PLM/OA BOM。
4. 点击开始检查。
5. 左侧按分类筛选：重点、需确认、缺位号、多余、多封装、高风险、已跳过、全部。
6. 相同物料、封装、状态和结论的位号会归并为一组；中间查看组内全部位号及共同详情。
7. 右侧查看复核规则。
8. 有替代组时，打开 **替代料兼容性** 页，逐个确认替代料封装与主料实际位号的网表封装是否兼容。
9. 下载封装检查报告和替代料封装兼容性报告。

提供语义清单后，实际贴装位号只取优先级 0 主料；替代料空位号不会被报成 BOM 缺失，也不会增加整板贴装数量。

### 9.4 结果分类

| 分类 | 含义 |
|---|---|
| 通过 | 网表封装和 BOM 字段匹配 |
| 近似通过 | 识别到常见尺寸或供应商型号近似匹配 |
| 需要确认 | 没有可靠匹配，需要人工看 |
| BOM 缺位号 | 网表有该位号，BOM 没有 |
| BOM 多余位号 | BOM 有该位号，网表没有 |
| 同料多封装 | 同一个物料编码对应多个网表封装 |
| 高风险封装 | BGA、QFN、eMMC、DDR、连接器等需要重点关注 |
| 已跳过 | NC、测试点、短接、安装孔或非贴片工艺对象 |

### 9.5 怎么处理重点项

- `BOM 缺位号`：确认是否漏导、误删、未贴或不应进 BOM。
- `BOM 多余位号`：确认是否手工添加、机构辅料、位号错误。
- `同料多封装`：确认同一个编码是否真的能对应多个封装；通常需要拆料号或修正封装。
- `高风险封装`：即使通过，也建议人工看一眼，尤其是 BGA、DDR、eMMC、连接器。
- `需要确认`：看网表封装、BOM 型号、描述、物料名称是否能对应。

## 10. 贴片位号视图

### 10.1 作用

把 `XY.txt` 中的全部器件位置与已处理 BOM 的装机判定叠加在同一块板面上，主要用于贴片资料发出前和首件检查时确认：

- 哪些位号正常贴装，哪些是 NC 或非贴片工艺项。
- BOM 有但坐标无、坐标有但 BOM 无的资料差异。
- 正反面、坐标、旋转和封装来源是否正确。
- 需要核对丝印细节时快速打开供应商原始位号图。

### 10.2 输入要求

1. **SMT 资料目录**：直接选择供应商交付的整个目录。平台按文件内容识别包含 `VERSION`、`UUNITS` 和坐标数据行的 XY 文件；DXF、Gerber、钢网、3D 和原理图会被忽略。
2. **处理后的 BOM**：选择 BOM 处理工具生成、可直接导入 PLM 或 OA 的成品 BOM。不要选择 Capture 原始 BOM。
3. **NC 汇总（本地 BOM 时建议）**：从 BOM 处理交付包中选择 NC 汇总，用来区分明确 NC、非贴片项和仅坐标有。通过历史记录选择 BOM 时会自动关联判定，不需要手工选择内部清单。
4. **旧版 BOM（可选）**：需要查看新增、删除或换料位置时选择。

坐标文件必须明确声明 `MILS` 或 `MM`。无法识别单位或坐标数据时平台会阻止生成，不会猜测单位。

### 10.3 操作步骤

1. 选择整个 SMT 资料目录。
2. 从历史记录选择已处理 BOM，或上传本地成品 BOM 与 NC 汇总。
3. 点击 **生成贴片位号视图**。平台会一次性载入全部坐标并按位号关联 BOM 状态。
4. 切换 **正面 / 背面**；背面会按翻板视角镜像并明确标注。
5. 在左侧输入一个或多个位号，点击列表项后板面会定位并显示物料编码、封装和判定原因。点击板面器件也会同步选中左侧位号。
6. 使用 **贴装状态、NC 专项、备料风险、版本差异**切换关注内容；切换只改变显示，不会重新读取文件。
7. 点击顶部资料差异数字查看 `BOM 有、坐标无` 和 `坐标有、BOM 无` 的完整清单。
8. 需要查看真实丝印时点击 **打开原始位号图**。PDF 只用于人工查看，不参与坐标计算。

### 10.4 结果怎么判断

| 结果 | 建议处理 |
|---|---|
| 贴装 | 位号存在于已处理成品 BOM |
| NC | 同次 BOM 处理判定为明确 NC 或用户排除 |
| 非贴片 | 判定为测试点、工艺项或当前 PCBA 范围外物料，与 NC 分开显示 |
| 仅坐标有 | XY 中有位号，但成品 BOM 和排除清单都无法解释；应确认漏料、NC 汇总缺失或资料不一致 |
| BOM 有、坐标无 | 成品 BOM 或排除清单中有位号，但 XY 没有坐标；应确认漏出坐标、非贴片物料或位号错误 |

### 10.5 常见错误提示

- `没有识别到有效 XY 坐标文件`：确认选择的是完整 SMT 交付目录，且坐标文件包含 `VERSION`、`UUNITS` 和以 `!` 分隔的数据行。
- `坐标文件缺少单位声明`：重新按标准格式导出，不能靠猜测单位继续处理。
- `只能使用通过平台上传或历史记录选择的文件`：不要在接口中填写电脑任意路径，应通过页面重新选择资料。
- `同时出现在成品 BOM 与排除清单`：平台按排除清单显示并给出提醒，应回到 BOM 处理结果核对这批位号。

## 14. 更新和卸载

### 14.1 检查更新

点击 **检查更新** 只检查远端是否有新版本，不会修改本地文件。

### 14.2 立即更新

点击 **立即更新** 会开始更新平台。更新时会显示进度和日志。

更新通常会保留：

- 历史记录。
- 上传文件。
- 输出文件。
- 本地配置。
- 用户自定义脚本。

更新后如页面没有变化，可以刷新浏览器或重新打开平台。

### 14.3 移除 Cadence 集成

如果只想让 Capture 菜单里不再出现平台入口，点击 **移除 Cadence 集成**。

这会移除 Capture 自动加载脚本，但保留平台本体和数据。

完整卸载请通过 Windows 设置里的应用卸载，或重新运行 `Insta360_HW_Setup.exe` 后选择 `Uninstall existing version`。

平台网页内不提供完整卸载按钮，避免本地 Web 服务删除自身时出现进度卡住、目录残留或注册表状态不一致。

如果只是暂时不用 Capture 菜单，优先使用“移除 Cadence 集成”。这个操作只移除 Capture 自动加载脚本，不删除平台本体、历史记录和本地数据。

- PLM BOM。
- OA BOM。
- NC/未贴汇总。
- 非贴片项汇总、BOM 判定记录和 BOM 语义清单。
- BOM 风险检查报告。
- BOM 差异报告。
- BOM 分层差异报告和机器可读 JSON。
- 网表差异报告。
- 贴片封装检查报告。
- 替代料封装兼容性报告。
- 单网络检查报告。
- 打包 zip。

建议项目交付时保留：

- 最终 PLM/OA BOM。
- NC/未贴汇总。
- BOM 风险检查报告。
- 贴片封装检查报告。
- 改版项目的 BOM 差异报告。
- 改版项目的网表差异报告。

## 16. 使用注意事项

1. BOM 处理尽量使用 Capture 正确导出的原始 BOM。
2. 贴片封装检查必须使用处理后的 PLM/OA BOM，不要用 Capture 原始 BOM。
3. 网表类工具直接选择 Allegro 目录，不要手动挑单个 dat 文件。
4. SH 开头位号属于屏蔽类强制审查，必须选择屏蔽支架、屏蔽罩或其他。
5. 屏蔽支架进入贴片 BOM；屏蔽罩属于非贴片范围排除，两者不能混用。
6. eMMC、DDR/LPDDR、NAND、UFS 出现时，要核对硬件版本号、容量、速率和替代关系。
7. 同一编码但描述/型号/名称/等级冲突时，不要无脑合并。
8. 高风险 Tcl 脚本执行前先备份设计。
9. 更新前如果正在处理关键项目，先下载当前输出文件。
10. 完整卸载只通过 Windows 设置或 `Insta360_HW_Setup.exe` 执行，平台网页内只负责移除 Cadence 集成。

## 17. 建议团队使用口径

为了让团队使用结果一致，建议约定：

- 所有正式 BOM 都先经过 BOM 处理。
- 提交 PLM/OA 前必须跑 BOM 风险检查。
- 改版评审必须附 BOM 差异报告。
- 涉及原理图/PCB 改动时，必须附网表差异报告。
- 贴片前必须跑贴片封装检查。
- 新增 Capture 脚本必须通过插件管理挂载，不手动改菜单。
- 更新平台前后，用同一组样例 BOM/网表做一次回归。

## 18. 后续可以继续做什么

平台后续可以继续补这些硬件工程师真正会用的工具：

- **版本变更影响报告**：把 BOM 差异、网表差异、封装检查和关键物料提醒合成一份改版报告。
- **关键网络专项检查**：DDR、eMMC、MIPI、USB、时钟、复位、电源使能等网络自动检查。
- **器件库属性体检**：检查 Capture 器件是否缺编码、缺封装、缺型号、字段不规范。
- **DFM/贴片准备清单**：自动整理 NC、测试点、安装孔、屏蔽支架、特殊工艺、高风险封装。
- **评审包一键生成**：把 BOM、网表、风险报告、封装报告和日志打成一个评审 zip。
- **替代料一致性检查**：检查同一物料或替代料的封装、规格、等级、描述是否一致。

## 19. 总结

Insta360 硬件提效平台的核心价值，是让 BOM 整理、风险检查、版本对比、网表检查、封装复核和 Capture 脚本管理形成统一流程。它不能替代硬件工程师判断，但可以把大量重复、琐碎、容易漏的检查提前自动筛出来，让工程师把精力放在真正需要判断的设计问题上。
